
# Московский зоопарк


Выделю ключевые моменты по логике классов:

### Animal

Пользователь сам задает порядковый номер животного, а также количество потребляемой им пищи
### Herbo

Уровень счастья определяется на основании потребляемого количества пищи в сутки.

### VetClinic

Решение о принятии животного в зоопарк принимается на основе генерации случайного числа.


## Применение SOLID 

### S - Принцип единственной ответственности

Класс `Zoo` отвечает за инвентаризацию.
Класс `VetClinic` отвечает за проверку здоровья животных.
Классы `Animal` и `Thing` и их наследники содержат только информацию о животных и их поведении.

### O - Принцип открытости/закрытости

Новые виды животных можно добавлять через наследование от `Animal`, не изменяя уже существующий код.
Класс `Herbo` (травоядные) расширяет `Animal`, добавляя свойство `Kindness`.

### L - Принцип подстановки Барбары Лисков

В коде можно заменить `Animal` его потомками не нарушая работу системы.

### I - Принцип разделения интерфейсов



### D - Принцип инверсии зависимостей

 В `Zoo` передаётся объект `VetClinic` через конструктор, а не создаётся внутри класса. Это позволяет заменить `VetClinic` на другую реализацию без изменения `Zoo`.
